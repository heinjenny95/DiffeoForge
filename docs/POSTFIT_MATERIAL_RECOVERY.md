# Preserve reconstruction marks through post-fit qualification

A normally completed native fit can need a denser original material grid for
spatial qualification. Previously, reconstruction marks bound to the earlier
ordered triangle array were checked directly against that refined array. The
material identity guard correctly rejected the mismatch, but the pilot classified
the post-fit exception as a failed calculation. A separate failed-backend recovery
route could then show an irrelevant shutdown warning. Retrying could spend a new
optimizer allowance although the native result was already saved.

## Exact material support

New conforming refinement stages record their sorted original split edges as
well as their existing child-to-parent face map. A versioned material-lineage
receipt binds the original and successive source grids, point and face counts,
ordered topology hashes, and every proof file's bytes and SHA-256.

Before using that lineage, qualification verifies the unchanged old vertices,
actual parent-edge incidence, exact appended edge midpoints, regenerated ordered
child triangles and winding, and regenerated parent indices. A marked ancestor
face therefore selects its exact descendants. No nearest-surface search, display
proxy, endpoint interpolation or inferred anatomical correspondence supplies that
mapping. The original mark and its inspected-surface identity remain unchanged.

The current endpoint, retained comparison, feedback measurement and later baseline
capture use the same verified support. Time-grid replay carries the spatial
ancestry only when the original material source is unchanged. Composed prefixes
retain the same source-grid binding. Unknown grids, invalid face IDs, missing
stages, reordered connectivity, forged or changed proof files fail closed.

Historical evaluations without a qualified lineage keep the original exact-grid
policy. Resuming their saved-field checks creates new, separately identified QC
outputs and proof; it does not rewrite their old evaluations. Verification and
mask transport poll cancellation between bounded stages and emit qualification
progress. Native equations, precision, tolerances, optimizer allowances, spatial
budgets and scientific acceptance thresholds are unchanged.

## Checks-only recovery

The pilot distinguishes a failed backend from incomplete checks of a normally
completed backend. New post-fit failures record their qualification phase and
bind the completed native evidence. Historical failures can also be recognized
from verified existing native metadata. A check-only recovery requires matching
configuration and manifest checksums, completed zero-exit result and lifecycle,
result-bound inventory, and token-bound completed shutdown with an empty backend
session. Numerical guard violations are excluded.

Presentation reads bounded metadata only. Dispatch freshly verifies protected
inputs and the complete native report before reusing the same run. Missing or
changed recorded completion evidence blocks dispatch rather than falling through
to another fit. A failure before any run was prepared keeps its normal failure
diagnosis. Existing cancelled-check receipts remain supported with current native
completion verification.

The explicit action is **Resume checks on saved fit · no new fitting**. This route
does not construct a native controller, run the optimizer, restore a failed field
or overwrite the completed native result. It appends study events and writes fresh
evaluation directories. Native checkpoint-continuation ancestry and cumulative
effort are retained independently of the check-only request context. Saved reviews
remain unchanged; completing checks does not create anatomical approval.

The view describes incomplete checks and suppresses the unrelated failed-backend
recovery message for these verified saved fits. Genuine numerical failures retain
their separate guard and review behavior. Resumed checks can still report a real
accuracy, preservation or surface-quality failure under the existing criteria.

## Verification boundary

Regression coverage includes exact multi-stage support on ancestor, intermediate
and current grids; tampering and re-signed false subdivision proofs; current and
retained regional distances; inherited-mark baseline capture; cancellation; legacy
and historical check-only recovery; missing completion evidence; native controller
exclusion; native continuation effort; and visible guided actions. Read-only
private-case qualification verifies the reported mismatch and exact descendant
support without fitting, replaying fields or changing owner evidence.

These are engineering checks. They do not establish anatomical correspondence,
registration quality, scientific convergence or a public-release qualification.
Source, packaged runtime, installed application and distributed installer retain
their separate provenance.
