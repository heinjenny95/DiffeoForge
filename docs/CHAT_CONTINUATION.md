## Handoff and completion rules

Keep two separate entry points when scientific interpretation and product
development move to different chats. Bind the scientific guide to the exact run,
effective configuration, preprocessing, QC release, PCA method and immutable
media manifests. Distinguish input units from normalized model coordinates,
physical shooting time from array indexes, and native tolerance from an iteration
cap or anatomical acceptance. Maintain specimen identities and original results.

For a recurring monitor, preserve its existing identity and full read-only
constraints; avoid a duplicate when transferring ownership to another chat.
Verify schedule, destination and notification intent separately. A handoff file
does not move an automation or establish a fresh remote observation. Keep private
monitor receipts outside the repository.

For an owner-authorized monitor transfer, update only the destination of the
existing automation. Verify readback against the saved configuration: identity,
full prompt, cadence, active status and notification settings must be preserved;
unrelated paused monitors must remain unchanged. Retain private before/after
receipts. A destination change does not require an extra server poll: keep the
last verified observation's timestamp explicit until the next scheduled check.

Every completed software, configuration or documentation change includes scoped
commit/push and the existing Google Docs Project log update with preservation
readback. Installer uploads remain on explicit request only. Recheck live app and
backend state and verify a complete recoverable backup before an authorized
installation. Never interrupt scientific work or discard unsaved changes to
deliver a build. Do not relaunch an old fit or manufacture approval during transfer.
