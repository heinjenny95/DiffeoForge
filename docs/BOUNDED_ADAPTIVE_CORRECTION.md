# Bounded adaptive correction

## Agreed behavior

An eligible single-form correction can prepare one adaptive action with a shared
allowance of at most 600 native optimizer iterations. The preparation records the
exact selected field, template, ordered control basis, red/fixed surface marks,
physical attachment/protection objective and evaluation protocol. It does not
rewrite a prepared legacy trial. Landmark guides and unsupported native scopes
keep their existing explicit workflow.

Before offering adaptation, the pilot checks both measurement directions for
each red area on the selected saved fit. When the marked volume has no surface
on one side, the pilot offers the protected single-trial workflow if eligible.
The same marks and selected field are used, with ordinary spatial, temporal,
intersection and preservation checks.

The first stage continues the selected field for at most 100 updates. If a red
region stalls, three short, controlled residual tests compare the original
basis, a nested basis with additional controls, and that same nested basis with
a narrower movement kernel. The attachment objective stays fixed. All three
tests start from the same retained field; new residual coefficients start at
zero. An improving feasible field can continue in bounded blocks. Stalling alone
does not establish that control-point count caused a poor fit.

Every stage, including a discarded test, consumes the same action allowance.
Preparation, fixed-field evaluation, fitting and checks share a two-hour deadline.
A hash-chained durable ledger reserves work before native dispatch. An unresolved
failed stage retains its reservation. Reopening, cancellation or a process failure
does not grant a fresh allowance or authorize a silent rerun. Line-search
evaluations and elapsed time remain separate from optimizer iteration counts.

New bounded candidate configurations also declare isolation of compiler-helper
Python processes. After installing its protected hooks, the parent removes the
run-local `PYTHONPATH` environment value. Its current import paths and hooks stay
loaded, while a later compiler query cannot initialize that active run again.
The declaration has an exact schema value. Unknown or mis-scoped declarations
fail closed. Without it, legacy startup assets render byte for byte as before.
Derived fixed-field evaluations clear the declaration on a configuration copy.

## Preservation and review

The incoming deformation is verified against finite accepted native state and
normal terminal/export/checkpoint evidence. Ordinary and regional objectives
have separate supported proof scopes. Legacy regional digests keep their exact
meaning. Changed inputs, material support, control order, coefficients, native
proofs or action declarations fail closed.

The controller measures every red region and checks explicit fixed regions and
the surrounding surface. It does not promote a newly failed quality result as a
continuation seed. Production children use the normal spatial, temporal,
intersection and preservation checks. These checks replay fixed fields; they
do not add hidden optimizer updates. A numerical recommendation is viewable,
but is distinct from an inspected starting-fit choice and anatomical approval.
The retained result is offered for explicit review even if the latest child
failed. Earlier fields, journals and approvals remain unchanged.

## Evidence for an extra 300 iterations

After a normally completed 600-iteration action, the pilot can recommend one
extra block of up to 300 optimizer iterations. The last stage must have reached
its optimizer cap and produced the retained fit by continuing the same
objective, control basis and movement scale. Each red area that still exceeds
its target must have reduced its worst bidirectional P95 surface distance by
more than the existing 2% progress floor. The fit must also pass the numerical
qualification and protection checks, including explicit green regions and the
surrounding surface. A stalled or regressed area, a failed stage, an unverified
check or an exhausted wall deadline alone provides no recommendation.

**Prepare +300 iterations** names this next step in the fixed footer and the
pilot explains the measured gains. The retained fit is also available for
review. Preparation verifies the saved field and the evidence again, recording
one separate continuation with the same marks and settings. The optimizer
starts when the researcher selects **Run +300 continuation**. The original
action keeps its 600-iteration ceiling; the extension has its own allowance,
normal cancellation and full fit checks. The extension leads back to review
after it finishes.

## Related interface and evaluation fixes

An unfinished saved pilot emphasizes Open saved pilot. Review/apply is primary
only after verified completion. Closed combo boxes forward wheel scrolling to
their surrounding scroll area; an open popup and keyboard selection retain their
normal behavior. A marking tool can set a sphere or 3D box and its dimensions
before the first point, retaining those settings for the next point.

Exact repeated fixed-field endpoints can reuse an explicitly passed cache. Its
key binds verified field/prefix bytes, source geometry, integration grid and
surface/point mode. Changed assets reject reuse; changed settings miss the cache.
Each request gets its own wrapper evidence. Mesh/filter cancellation propagates
through preparation and fixed-field evaluation, including the adaptive deadline.
Display proxies remain separate from scientific surfaces.

## Acceptance and limits

Automated software tests exercise cumulative budgets, failed reservations,
tampering, cancellation, source identity, ordinary/regional guard separation,
exact endpoint reuse and Qt interaction. These tests do not establish anatomical
accuracy, a general speedup, first-use usability or platform qualification.

Prospective native experiments use isolated copies and retain an explicit
evaluation scope. A reduced physics/ROI experiment with unassessed spatial,
temporal or intersection checks cannot supply a trusted production seed, claim
full qualification or grant anatomical approval. Scientific validation and
installed/distributed package verification must be recorded separately.
