# v153 — choose a method, improve, then validate

The owner-authorized redesign replaces the blocked budget-extension route and
separates a provisional starting-method preference from anatomical acceptance.
Both new projects and saved guided pilots use the new interface. Existing saved
manifests and reviews are preserved; an explicit next preparation creates a new
v3 successor. Older v2 evidence retains its original verification rules.

## Guided sequence

1. The existing geometry-diversity plan proposes a small set of distinct forms,
   with manual required specimens/strata retained. This selected set is separate
   from the number of fitting attempts. Saved pilot membership is not silently
   reduced to make a failed form disappear.
2. Compare Current and Varifold on one form. Each has its own inspection and
   action. A reviewed, technically valid but visually rejected fit can be chosen
   as a **starting method** without becoming approved. When both are acceptable,
   choose one directly or explicitly compare another contrasting form. Runtime
   is context, not evidence that a method is anatomically superior.
3. Improve the chosen fit before confirming settings. Missing shape or relevant
   local detail means **Needs improvement**; a rough outline alone does not grant
   final acceptance. The marked-region/symptom heuristic explains one proposed
   change. Alternative adjustments and the settings before the last trial remain
   accessible. Completed identical combinations are not repeatedly prepared by
   default. The hypotheses do not identify a unique cause or promise recovery.
4. An explicitly suitable fit permits single-form coverage checks on the same
   settings. A failed contrasting form leads immediately to refinement there.
   Parameter changes reset compatible coverage, retain all earlier evidence and
   prioritize known difficult forms for renewed checks. Before preparing a change,
   the UI declares the next one-target test and the other checks/joint fit still
   needed if it succeeds.
5. Complete compatible coverage permits a joint pilot fit. Every joint specimen
   requires visual review. A failed joint specimen can lead back to a targeted
   one-form refinement; it cannot be bypassed by a method preference. The accepted
   joint model still passes through the existing numerical qualification gates.

## Resource and execution control

The interactive protocol has no arbitrary total trial cap. Each action declares
and prepares one target/variant, except an explicit two-method comparison or the
explicit joint batch. Every batch requires its own Run. Preparation, preference,
inspection and history restore never launch a native fit. Trial totals are shown
as accounting, not a stopping rule. Repeated non-improving changes prompt input,
alignment and template checks; a failed fit is never automatically approved.

Immutable source/run/settings references bind preference, refinement baselines,
regions and old true approvals separately. Withdrawn compatible approvals or
changed source bytes remain invalidating. Preferences do not enter the approval
ledger. Repeated button clicks cannot replace an active worker or dispatch a
second transition. Persistent transition errors and lazy saved comparisons remain.
Ancestor verification is shared within one read-only operation to avoid repeated
history parsing; the scope ends before mutations and is recreated on every action.

This change preserves native LDDMM equations, scientific geometry, control-grid
construction, stopping criteria and the existing declared parameter hypotheses.
Synthetic and exact-runtime checks qualify software flow only; biological
suitability, correspondence and independent owner acceptance remain separate.
