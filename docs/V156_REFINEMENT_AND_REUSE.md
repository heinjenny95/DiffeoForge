# v156 — preserve useful fits and reuse verified input work

Owner authorization, 23 October 2026, replaces collection-only status for the
recently collected refinement, cross-project deep-validation and repeated pilot
preparation reports. Existing source studies and scientific outputs remain intact;
development and delivery start no new scientific fits.

The saved chain confirmed two different problems: previous proposals changed some
widths by a factor of two, and retaining parameter values did not initialize the
next fit from the retained deformation. New adaptive detail proposals change one
attachment/noise setting by 10%, with smaller alternatives if that exact test was
already tried. They keep the selected starting fit, method, deformation kernel and
control grid. A failed hypothesis does not automatically widen into method/basis
search. Those alternatives remain explicit choices.

Compatible singleton refinements copy the original frozen control points and the
verified native fitted momenta. Binding checks the exact template/target contents,
subject order, method, deformation kernel, time integration, precision and frozen
basis. A method/basis change or multi-subject source declares fresh initialization.
This is a new optimization with learned initialization, not checkpoint continuation
or preservation of optimizer history. Every new fit still requires Run and fresh
visual review. Preparing a trial never starts it.

Relative feedback keeps a useful starting fit without treating it as anatomical
approval. The retained fit is directly inspectable; the first fit is directly
recoverable if another starting point is selected. Comparable whole-shape sampled
distances flag regressions, with regional checks for marked patches. A gross global
regression cannot be promoted merely by the Better response. Explicit user choice
remains available. Feedback without a marked patch now omits empty patch lists,
repairing the modal save failure exposed by the complete GUI journey.

Deep surface checks now have a desktop-wide per-content/rules-version cache.
Compatible earlier project evidence is migrated; copied/renamed files reuse their
checks after fresh hashes. Missing/changed files are inspected individually;
corrupt or incompatible evidence falls back to inspection. Warnings and failures
remain failures. Project/cohort/landmark and GPA decisions remain separate. The
explicit Revalidate meshes action forces inspection when requested.

Pilot preparation also reuses verified VTK metadata and exact prior alignment
publications across recent projects. Alignment reuse requires all input, landmark,
template, transform and preprocessing bindings to agree and makes a separate,
hash-verified project copy. It never hardlinks live project files. Changing
landmarks invalidates alignment/QC while retaining raw mesh-inspection evidence.
Scalar measurement rules are versioned independently of GUI releases, with
verified migration of old compatible entries. Progress distinguishes content I/O,
inspection, reused checks and transformation; logs record cache misses and phases.

Visualization adds an explicit all-heatmaps button covering every available
PC/sign/map kind and a compact static-map legend. Newly generated media version 3
identifies the mean reference, signed normal/model units and the same endpoint's
six views; score-path wording is reserved for movies. Existing version-2 media
remain readable and immutable; their embedded historical captions are unchanged.
Independent owner verification of the reported result/overview remains open.

Focused regressions cover physical field binding, incompatible changes, retained
references, global guards, cache migration/partial invalidation, failed topology,
force revalidation and exact cross-project alignment reuse. Complete synthetic GUI
journeys exercise real modal feedback/history, correction and review recording;
native scientific dispatch is forbidden. One existing saved native field was
read-only verified for reuse eligibility without changing its source or fitting.

Source, frozen and installed checks, verified backup and fresh idle guards, GitHub
and Project log updates are delivery gates. Biological improvement, independent
owner first use, full large-cohort preparation benchmarks and earlier external
platform/research gates remain prospective. Software checks do not certify those.
