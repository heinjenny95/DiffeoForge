# v104 — early visual filters for pilot stages 2 and 3

Stages 2 and 3 can now calculate each option on a chosen difficult specimen
before spending time on a joint comparison. An optional second, contrasting
specimen provides another filter. **Start early specimen review** calculates
one screen and waits. **Keep option → next screen** keeps its parameters for
joint testing; **Discard option → next screen** omits that option. Once the
queue is decided, **Run kept options with all N specimens** starts the joint
comparison. Uncheck the screening option to use the ordinary complete comparison.

The candidate's verified learned template and compatible controls are frozen for
the screen. Compatible initial momenta use exactly the chosen subject row; a
changed grid/kernel does not import an incompatible field. The target is the
bound original scientific mesh, not a display proxy. Screen momentum fields and
QC passes never seed, replace or approve the joint atlas. Surviving joint results
require all-specimen visual QC. The prior approved joint fit remains available
through the existing keep action even if all alternatives are discarded.

The hash-chained parent ledger binds source settings, reference files, child
studies and actual child review decisions. Reopening resumes the pending screen
without repeating a completed calculation. Cancellation targets the active child
and preserves the queue. An engine failure excludes the option with a technical
failure record, without inventing an anatomical rejection. There is no elapsed
time cutoff. Each joint run retains the normal shared-template optimization.

## Complete numerical comparison in stage 4

Stage 4 has no singleton filter: every timepoint option uses the complete pilot.
Before the first run, collapsed numerical controls record engineering criteria:
atlas RMS / bound reference diagonal (default 0.5%), relative total objective
difference (1%) and the largest per-specimen relative residual difference (1%).
These are adjustable prospective tolerances, not validated biological cutoffs.

Recommend the smallest count meeting every criterion against the next finer
completed discretization, with valid geometry and optimizer convergence. Missing
specimen evidence, an excessive difference or a failed finer reference prevents
qualification. The largest tested count has no finer reference and cannot certify
itself. No qualified option means no numerical winner. Runtime does not override
these checks. Recorded visual rejection remains a blocker; numerical qualification
never supplies anatomical approval. Final reports retain the declaration.

Already-started legacy stage-4 comparisons preserve their prior interpretation;
new criteria are not retroactively imposed on old results. Existing completed
stage-2/3 options are kept, rather than recomputed as screens. Historical studies
remain readable. The main UI resumes the chosen series' verified current pointer;
saved-series labels show time, individual approval count, current joint stage and
review status. Current series and rejected joint attempts are distinguishable.

## Verification and limits

Synthetic regressions cover singleton inputs/initialization, pause and persistence,
rejection before joint dispatch, optional second-specimen rejection, evidence
tampering, cancellation, technical failure, baseline preservation, separate joint
QC, desktop actions, complete stage-4 dispatch, worst-specimen numerical checks,
missing evidence, prospective tolerance binding and legacy compatibility.
Existing study, sequential-fit and review-dialog regression suites are included.
Build, local delivery and hashes are recorded separately after verification.

A singleton fit with frozen reference is an early rejection filter; it cannot
predict the optimum of the shared-template joint atlas. It can also reject an
option that would work jointly. Screening remains optional. Prospective timing,
independent first-use review and dataset anatomical acceptance remain user checks.
No private fit, atlas, parameter tuning or scientific approval is part of this
software update. Drive distribution remains request-only.
